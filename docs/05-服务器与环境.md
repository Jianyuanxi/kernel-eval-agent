## 2. 登录服务器

全组共用一把密钥 `kernel_eval_team_ed25519`（在自己那块的分工文件夹里，**不要提交到仓库，不要发到群外**）。

**Windows（PowerShell）**：

```powershell
mkdir $env:USERPROFILE\.ssh -Force
copy kernel_eval_team_ed25519 $env:USERPROFILE\.ssh\
# OpenSSH 要求私钥只有自己能读，否则报 UNPROTECTED PRIVATE KEY FILE
icacls $env:USERPROFILE\.ssh\kernel_eval_team_ed25519 /inheritance:r /grant:r "$($env:USERNAME):(R)"
```

再把下面这段追加到 `C:\Users\你的用户名\.ssh\config`（没有就新建，无扩展名）：

```text
Host kernel-eval
  HostName 132.232.242.186
  User ubuntu
  IdentityFile ~/.ssh/kernel_eval_team_ed25519
  IdentitiesOnly yes
  ServerAliveInterval 30
```

之后 `ssh kernel-eval` 就能登录；`scp 文件 kernel-eval:~/` 传文件。VS Code 装 Remote - SSH 插件后也能直接选 `kernel-eval` 打开服务器上的目录。

**macOS / Linux / WSL**：私钥放 `~/.ssh/`，`chmod 600`，config 同上。

**在服务器上的规矩**：

- 自己的东西只放 `~/dev/你的拼音名/`。
- 不要动 `/opt/dify`、`/opt/kernel-eval`、`/data/kernel-eval/ref`、`/data/kernel-eval/samples`（这些归块 1）。
- 不要 `docker system prune`、不要删别人的容器和镜像、不要重启 Docker、不要改防火墙和 SSH 配置。
- 跑完的容器自己清掉；长时间占 CPU 的任务先在群里说一声（服务器同时跑着 Dify）。

## 4. 代码怎么上服务器

服务器访问不了 GitHub，统一用仓库里的两个脚本（在自己电脑的 Git Bash 或 WSL 里运行）：

| 脚本 | 谁用 | 做什么 |
|---|---|---|
| `bash deploy/devsync.sh 你的拼音名` | 所有人 | 把本地工作区（含没提交的改动）传到服务器 `~/dev/你的拼音名/`，用来在服务器上跑需要 Docker 的测试 |
| `bash deploy/deploy.sh` | 块 1 | 把 `origin/main` 打包传上去，装依赖、构建前端、重启后端 |

在服务器上跑测试：

```bash
ssh kernel-eval
cd ~/dev/你的拼音名/backend
KE_DATA_ROOT=/tmp/ke-你的拼音名 /opt/kernel-eval/venv/bin/python -m pytest -q tests/你的测试.py
```

| 块 | 要装的 | 能在 Windows 上做吗 |
|---|---|---|

| 3、4 | 同上，另外需要 Docker + Linux | 本机装 WSL2 + Docker，或者直接用服务器（devsync） |

```bash

cd kernel-eval-agent
python -m venv backend/.venv
backend/.venv/Scripts/pip install -r backend/requirements.txt -i https://mirrors.cloud.tencent.com/pypi/simple   # Windows
# macOS/Linux: backend/.venv/bin/pip install ...
```

## 6. Dify 与大模型

| 项 | 值 |
|---|---|
| Dify 版本 | 1.17.1（固定，不升级） |
| 模型供应商 | 腾讯云 TokenHub，Dify 里用“OpenAI-API-compatible”插件接入 |
| API 地址 | `https://tokenhub.tencentmaas.com/v1` |
| 对话模型 | `deepseek/deepseek-flash`（主用），`glm-5.3-flash`（备选，块 1 对比后定） |
| 函数调用方式 | Tool Call |
| 向量模型 | `kinfra-text-embedding-0.6b` |
| 重排模型 | 没有（TokenHub 不提供），知识库用混合检索 + 权重设置 |
| 智能体应用类型 | Agent（函数调用模式），工具 = 导入 `contracts/tools.openapi.yaml` 的自定义工具 + 知识库 |

- **TokenHub API Key 只有组长有**，已经由组长填进 Dify 的模型供应商设置里；组员不需要、也不要往仓库或文件里写任何密钥。
- Dify 账号由组长在 Dify 后台“成员”里邀请（没配邮件，邀请后会显示一个激活链接，组长发给你）。
- 工具服务地址：Dify 调我们的工具走公网 `http://132.232.242.186/tools/...`（经 Dify 自带的 SSRF 代理，2026-10-18 实测可达）。内网地址会被 SSRF 代理拦掉，不要改。
- 工具令牌 `KE_TOOL_TOKEN` 在服务器 `/opt/kernel-eval/kernel-eval.env` 里（`grep ^KE_TOOL_TOKEN= /opt/kernel-eval/kernel-eval.env`），填到 Dify 自定义工具的鉴权里（API Key → 请求头 `X-Tool-Token`）。
- Dify 应用的 API 密钥（`app-` 开头）由块 5 建好应用后交给块 1，填进 `kernel-eval.env` 的 `KE_DIFY_APP_KEY`。

## 7. 沙箱的安全设置

每次编译/运行/扫描都起一个一次性容器（`sandbox.run_in_sandbox`）：

```text
docker run --rm -i --network none --user <uid>:<gid> --cap-drop ALL --security-opt no-new-privileges \
  --cpus 2 --memory 1g --pids-limit 256 -v <工作目录>:/workspace -w /workspace kernel-eval-sandbox:0.1 <命令>
```

断网、非 root、限 CPU/内存/进程数，超时按容器名强制删除，输出最多保留 256KB。只挂载任务自己的工作目录，命令由我们的代码拼，不接受模型传来的命令。
