# 03 评分规则（冻结）

把老师认可的《评测标准方案》写成可以直接编程的规则。块 6 的 `compute_score` 按本文实现，**同样的输入必须得到同样的输出**。分数全部由代码算，大模型只负责判断功能点状态、找缺陷、评规范档次。

示例：`contracts/examples/score_result.json`（样例 1，79 分，中等），逐项推算见第 7 节。

## 1. 四个评分项

| key | 名称 | 满分 | 依据 |
|---|---|---|---|
| compile_run | 编译与运行 | 20 | BuildResult、RunResult |
| features | 功能完成度 | 40 | ReviewResult.features |
| reliability | 代码可靠性 | 25 | Report.defects（校验后） |
| style | 规范与可读性 | 15 | ReviewResult.style |

## 2. 编译与运行（20）

| 情况 | 得分 |
|---|---|
| 编译 passed | 10 分，再按工程内警告数扣：0 条不扣，1–10 条扣 1，超过 10 条扣 2 |
| 编译 failed | 0 分，并且**功能完成度也记 0**（评分表原文：编译不通过时，编译与运行、功能完成度两项记 0 分） |
| 运行 passed（启动且没有异常刷屏） | 加 10 分 |
| 运行 failed / skipped | 加 0 分 |

- 警告数用 `BuildResult.warnings`（只算 `in_project=true` 的，链接器警告不算）。
- **我们工具自己出错**（build 或 run 的 status=error）：这一项记 `score=null`（不计分），reasons 写“评测工具出错，本项不计分”，按第 6 节折算。不能因为我们的工具坏了扣学生的分。
- 代码片段工程（mode=fragment）：这一项 `score=null`，reasons 写“只提交了代码片段，不评编译与运行”。

## 3. 功能完成度（40）

8 个功能点，每个 5 分：done 5、partial 2.5、none 0。

| 编号 | 功能点 |
|---|---|
| F_UART | 串口打印 |
| F_EXC | 异常处理 |
| F_TIMER | 时钟中断 |
| F_TASK | 任务创建与切换 |
| F_SCHED | 任务调度 |
| F_SEM | 信号量 |
| F_SHELL | shell 命令 |
| F_INNOV | 创新功能 |

完整工程编译 failed 时本项直接记 0，reasons 写“编译不通过，按评分表本项记 0 分”，不看模型的判断。reasons 里列出完成、部分完成、未完成各几项及名称。

## 4. 代码可靠性（25）

从 25 分起扣，扣到 0 为止：严重 5 分、一般 2 分、轻微 1 分（`SEVERITY_PENALTY`）。

- 只扣 `Report.defects` 里的缺陷（已经过块 1 的校验、去重，见 docs/02 第 8 节）。
- `in_baseline_unchanged=true`（文件和参考代码完全相同）的缺陷**不扣分**，`counted=false`。
- 其余缺陷 `counted=true`，每条在 `deductions` 里记一行（defect_index 是它在 `Report.defects` 里的下标，按下标顺序）。
- reasons 写每个级别的个数和扣分，以及“参考代码原有的 N 个问题不扣分”。

## 5. 规范与可读性（15）

good 15、medium 10、poor 5。reasons 写“好/中/差：”加模型给的理由。

## 6. 总分与等级

```text
raw_total = 所有 score 不为 null 的评分项之和
total     = int(raw_total / 这些项的满分之和 × 100 + 0.5)
```

- 完整工程四项都计分时满分之和是 100，total 就是 raw_total 四舍五入。
- 代码片段工程是三项之和 / 80 × 100。
- 等级：≥90 优秀、≥80 良好、≥70 中等、≥60 及格，其余不及格。
- `raw_total` 保留原始小数（例如 78.5），不提前取整。

## 7. 样例 1 推算（对应 contracts/examples）

| 项 | 依据 | 得分 |
|---|---|---|
| 编译与运行 | 编译通过、2 条警告扣 1 → 9；运行通过 +10 | 19 |
| 功能完成度 | 7 项 done，F_SCHED partial：7×5 + 2.5 | 37.5 |

## 8. clang 检查器 → 缺陷类型（块 4 用）

块 4 把每条 clang 告警的 checker 转成 `Finding.defect_type`，级别按 `DEFECT_TYPES` 取。按顺序匹配，第一条命中为准：

| checker（前缀匹配） | 附加条件（message 包含） | defect_type |
|---|---|---|
| core.NullDereference、core.NonNullParamChecker、nullability.* | | NULL_DEREF |
| core.CallAndMessage | null | NULL_DEREF |
| core.CallAndMessage | uninitialized、garbage | UNINIT_VAR |
| core.DivideZero | | DIV_ZERO |
| core.uninitialized.*、core.UndefinedBinaryOperatorResult | | UNINIT_VAR |
| core.StackAddressEscape、core.StackAddrEscapeBase | | WILD_POINTER |
| alpha.security.ArrayBoundV2、security.ArrayBound、alpha.unix.cstring.OutOfBounds | | OUT_OF_BOUNDS |
| unix.Malloc、unix.MallocSizeof、cplusplus.NewDelete | Use of memory after | USE_AFTER_FREE |
| unix.Malloc | Attempt to free released | DOUBLE_FREE |
| unix.Malloc | leak | MEM_LEAK |
| deadcode.* | | UNUSED |
| security.insecureAPI.* | | OTHER_MINOR |
| core.* | | OTHER_NORMAL |
| 其他 | | null（不映射，智能体自己判断） |

默认只用 clang 自带的默认检查器；块 4 可以额外打开 `alpha.security.ArrayBoundV2`。要加别的检查器，先在这张表里补映射（属于改规则，按 docs/02 第 10 节走）。

## 9. 和《评测标准方案》的对应

- 评分表四项分值、编译不过记 0、缺陷扣分、规范三档、等级划分：原样照搬。
- 《评测标准方案》里“警告酌情扣 1–2 分”在这里定成按条数扣，避免每次不一样。
- 《评测标准方案》缺陷条目示例写的是“[严重] 内存泄漏”，但分级表里内存泄漏属于“一般”。以分级表为准，示例已改成“[一般]”。
- 片段折算、工具出错不计分、参考代码原有缺陷不扣分是我们补的细则，评分表没写到。
