# 04 开发规范

每个人都用自己的 AI（Codex 等）写代码。这份规范和仓库根目录的 `AGENTS.md` 内容一致，`AGENTS.md` 是给 AI 看的精简版，Codex 会自动读取。

## 1. 每块管哪些目录

**只改自己块的目录。** 要改别人的目录，先在群里说，由那一块的人改，或者提 PR 请他审。

| 块 | 自己的目录 | 只读使用 |
|---|---|---|
| 1 集成与部署 | `backend/app/core/`、`backend/app/schemas/`、`backend/app/main.py`、`backend/app/config.py`、`backend/requirements.txt`、`backend/tests/`（公共测试）、`contracts/`、`deploy/`、`docs/`、`.github/`、根目录文件 | 全部 |
| 2 工程处理 | `backend/app/ingest/`、`backend/tests/ingest/` | schemas、examples |
| 3 编译与运行 | `backend/app/buildrun/`、`backend/tests/buildrun/`、`sandbox/` | schemas、examples |
| 4 静态分析与缺陷测试 | `backend/app/analyze/`、`backend/tests/analyze/`、`evaluation/` | `buildrun/sandbox.py`、schemas |
| 5 智能体与知识库 | `agent/`（dsl、prompts、knowledge） | contracts、examples |
| 6 网页、评分与追问 | `frontend/`、`backend/app/scoring/`、`backend/app/followup/`、`backend/tests/scoring/`、`backend/tests/followup/`、`acceptance/` | schemas、examples、`agent/prompts/followup.md` |

例外：块 4 需要往沙箱镜像里加东西时，改 `sandbox/Dockerfile` 并在 PR 里请块 3 审。

## 2. 分支与合并

- `main` 只能通过 PR 合并，由块 1（组长）审核合并；块 1 自己的 PR 请任意一位组员审。
- **每个人只推自己的分支**，不推 main、不推别人的分支、不 `--force`。
- 分支名 `blockN-简短英文`，例如 `block2-ingest`、`block6-report-page`。
- 每完成任务说明里的一个阶段就提一个 PR，不攒到最后；阶段内每做完一个小功能就 commit 并 push 到自己的分支。
- PR 用 `gh pr create` 提（没有 gh 就用浏览器打开 compare 页面），标题“块N 阶段M：一句话”；GitHub Actions 的 pytest 必须通过；描述里写完成了哪个阶段、做了什么、怎么测的（贴命令和结果）、还没做什么。
- 开工前和提 PR 前先 `git fetch && git merge origin/main`，解决冲突后再推（不用 rebase，免得要强推）。
- 具体步骤写在 `AGENTS.md` 的“工作流程”，AI 会照着自己做。

## 3. 提交信息

Conventional Commits，类型用英文，描述用中文：

```text
feat: 实现 zip 解压与工程识别
fix: 修复 GBK 文件名解压乱码
test: 补样例 2 多工程识别测试
docs: 更新块 3 踩坑记录
```

用 AI 写的提交可以保留 AI 加的 Co-Authored-By 行。

## 4. 测试

- 每块在 `backend/tests/<模块名>/` 下写自己的测试（前端除外），`cd backend && python -m pytest -q` 必须全部通过。
- 只能在服务器上跑的测试（需要 Docker、沙箱镜像）加 `@pytest.mark.sandbox`（`tests/conftest.py` 检查 docker 命令、守护进程和镜像），保证 CI 和 Windows 上能跳过；服务器上加 `KE_REQUIRE_SANDBOX=1` 跑，不允许跳过。
- 用到测试样例的测试从 `app.config.SAMPLES_ROOT` 找样例，找不到就 `pytest.skip`（CI 上没有样例）。
- 不准删别人的测试、不准为了通过改断言或改 `contracts/examples/`。
- 改完代码要真的跑一遍测试，看到通过再说“做完了”。

## 5. 不能进仓库的东西

| 东西 | 原因 | 放哪 |
|---|---|---|
| 测试样例（往届学生代码） | 隐私 | 本地 `samples/`、服务器 `/data/kernel-eval/samples/`（`.gitignore` 已忽略） |
| 植入缺陷后的样例、补丁 | 含学生代码 | `evaluation/patches/`（已忽略） |
| 任何密钥：服务器私钥、TokenHub Key、Dify 应用密钥、工具令牌 | 安全 | 只在自己电脑和服务器配置文件里 |
| `.env`、`backend/data/`、`node_modules/`、`.venv/` | 运行数据 | 已忽略 |

**往届学生的姓名、学号不能出现在仓库、文档、PPT 里**，样例一律叫“样例 1–4”。

## 6. 代码风格

- Python 3.12，类型注解，函数和模块写一句中文 docstring 说明做什么；不加没人要的抽象和配置项。
- 读文件一律 `encoding="utf-8", errors="replace"`（学生代码里有 GBK 注释）。
- 路径用 `pathlib.Path`；写进结果的路径一律相对、用 `/`。
- 调外部命令用 `subprocess.run([...])` 列表形式，不用 `shell=True`，必须带超时。
- 前端：Vue 3 + Vite + JavaScript，`<script setup>`；不引入 TypeScript 和状态管理库。

## 7. 依赖

- Python 依赖统一在 `backend/requirements.txt`，版本固定。要加依赖先在群里说，由块 1 加。
- 前端依赖在 `frontend/package.json`，块 6 自己管，提交 `package-lock.json`。

## 8. 每个人都要交的

- **踩坑记录**：在自己块的目录下维护 `NOTES.md`（块 5 放 `agent/NOTES.md`，块 6 放 `frontend/NOTES.md`，块 1 放 `deploy/NOTES.md`），随手记装环境、遇到的问题和解决办法。最后汇总成 Word 指导书里自己那一章。
- **进度**：每个阶段的 PR 提交或合并后在群里说一声（AI 每次结束会给一段进度摘要，直接转发即可）。不规定固定时间。
- 答辩 PPT 到时全组一起做，不在各块的任务里。
