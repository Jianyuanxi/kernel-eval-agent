# 块 3：编译与运行

> 给负责本块的同学和他的 AI 看。先读仓库根目录 `AGENTS.md`，再读本文。接口细节以 `docs/02-接口规范.md`（尤其第 7 节已验证的规则）和 `backend/app/schemas/buildrun.py` 为准。

## 1. 目标

在沙箱容器里把学生的 MiniEuler 工程交叉编译出来，再放进 QEMU 里跑 20 秒，抓串口输出、给 shell 发几条命令，整理成结构化结果。另外维护全组共用的沙箱执行器和沙箱镜像。

## 2. 范围

- 只改 `backend/app/buildrun/`、`backend/tests/buildrun/`、`sandbox/`，踩坑记录写 `backend/app/buildrun/NOTES.md`。
- `sandbox.py` 里 `run_in_sandbox` 和 `prepare_workspace` 的签名不能改（块 4 也在用），可以加固内部实现。
- 需要 Docker + Linux：本机 WSL2 装 Docker，或者用服务器（`bash deploy/devsync.sh 你的拼音名` 同步代码后在服务器上跑测试，见 docs/05 第 4 节）。服务器上已经有镜像 `kernel-eval-sandbox:0.1`。


示例输出：`contracts/examples/build_result.json`、`run_result.json`（样例 1 的真实结果）。

## 4. 详细要求

### 4.1 build

1. `project.buildable` 为 false → 直接返回 status=unsupported。
2. `prepare_workspace(project_dir, work_dir)`，返回值写进 `toolchain_rewritten`。
3. 在沙箱里配置 + 构建（工程根下有 `src/CMakeLists.txt` 用 `-S src`，否则 `-S .`）：
   ```text
   sh -c 'cmake -S src -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build -j2'
   ```
   总超时 `config.BUILD_TIMEOUT_S`（180 秒）；超时 → status=failed，诊断里加一条 error “编译超时”。
4. 完整输出写 `log_dir/build.log`，`log_file` 填这个路径（块 1 会转成相对路径），`log_tail` 取最后 3000 字符。
5. **解析诊断**：匹配 `^(/workspace/[^:]+):(\d+):(\d+): (warning|error|fatal error): (.*)$`，路径去掉 `/workspace/` 前缀后相对工程根，in_project=true；链接器的 `ld: warning: ...` 记 in_project=false、path 为空串。按出现顺序编号 B1、B2…，最多 100 条。`warnings` = in_project 的警告数，`errors` = 错误数。
6. **找产物**：依次 `build/miniEuler`、`build/miniEuler.elf`、`build/` 下任意 `*.elf`；`artifact` 填相对 work_dir 的路径。`has_compile_commands` = `build/compile_commands.json` 是否存在。
7. status：命令退出码 0 且找到产物 → passed；否则 failed。
8. docker 本身起不来 → `run_in_sandbox` 抛 SandboxError，**不要捕获**，块 1 会转成 status=error。

### 4.2 run

1. `build_result.status != "passed"` → status=skipped。
2. **GIC 版本**：取工程根 `runMiniEuler.sh`（在 work_dir 里）最后一个 `gic-version=(\d)`；没有就在 `src/` 下的 .c/.h/.S 里搜 `gic-version=(\d)` 或 `GIC_VERSION\s+(\d)`；都没有用 2。
3. **启动**（沙箱里）：
   ```text
   timeout <KE_RUN_WINDOW_S> qemu-system-aarch64 -machine virt,gic-version=N -m 1024M -cpu cortex-a53 \
     -nographic -nic none -serial mon:stdio -kernel <artifact>
   ```
   `run_in_sandbox` 的 timeout_s 给 RUN_WINDOW_S + 15。退出码 124 是窗口到点，正常。
4. **发 shell 命令**：用 `stdin_steps`，第一条前等 5 秒，之后每条间隔 2 秒，每条以 `\r` 结尾。命令列表：
   - 固定先发 `top`、`tick`（MiniEuler 课程实验里的标准命令）；
   - 再从工程 `src/shell/` 下的 .c 文件里提取命令名：匹配 `strcmp\s*\(\s*\w+\s*,\s*"(\w+)"\s*\)` 和 `strncmp(...,"(\w+)"...)`，以及命令表里形如 `{"(\w+)",` 的字符串；去重，按出现顺序；
   - 合计最多 6 条（样例 1 应该得到 `top`、`tick`、`mem`）。
5. **整理输出**：`\r\n`、`\r` → `\n`，再把连续多个 `\n` 合并成一个；去掉 `\x00`。
6. **识别提示符**：在输出里找第一个形如 `^(\S[^\n]{0,30}?[#$>] )` 且后面紧跟着命令回显的行首串（样例 1 是 `miniEuler # `）；找不到为 null。
7. **切分**：第一个提示符之前（找不到提示符就是全部）的前 4000 字符是 `boot_output`（R1）。之后按提示符切段，每段第一行是命令回显，其余是这条命令的输出（最多 4000 字符），依次编号 R2、R3…。
8. **booted**：去掉 QEMU 自己的输出（以 `qemu-system-aarch64:` 开头的行）后还有任何非空字符 → true（样例 2 的 lab1 只输出 `AArch64 Bare Metal` 也算）。
9. **没有任何串口输出**时，换另一个 GIC 版本（2↔3）重试一次，`tried_gic` 记录试过的版本，`gic_version` 填最后用的。
10. **异常**：
    - 同一非空行出现 ≥50 次 → `EXC_STORM`（样例 2 lab6_pro 会刷 `Catch a exception.`）
    - 输出被截断（ExecResult.truncated）→ `OUTPUT_TRUNCATED`
    - 一个字符都没有 → `NO_OUTPUT`
11. status：booted 且没有 EXC_STORM → passed；否则 failed。
12. **feature_hints**（只是提示，给智能体参考）：booted → F_UART；有 tick 命令且输出里有数字 → F_TIMER；top 输出里有 ≥1 行任务信息 → F_TASK；任一命令有非空输出 → F_SHELL。
13. 完整原始输出写 `log_dir/run.log`，`output_bytes` 填截断前总字节数。

## 5. 测试

`backend/tests/buildrun/` 下，需要 Docker 的测试加 `@pytest.mark.skipif(shutil.which("docker") is None, reason="需要 Docker")`，需要样例的找不到就 skip。必须有：

| 测试 | 预期 |
|---|---|
| 样例 1 build | passed，artifact=build/miniEuler，has_compile_commands=true，toolchain_rewritten 非空 |
| 样例 4 build | passed，artifact=build/miniEuler.elf |
| 样例 2 lab10 build + run | passed，gic_version=3（没有运行脚本，从源码注释取） |
| 样例 1 build 前把 `src/main.c` 第 1 行改成乱码 | failed，diagnostics 里有 path=src/main.c 的 error |
| 样例 1 run | passed，booted，shell_prompt=`miniEuler # `，commands 依次是 top、tick、mem，输出里没有连续空行 |
| 样例 2 lab6_pro run | failed，anomalies 含 EXC_STORM，20 多秒内结束 |
| 样例 2 lab1 run | booted=true |
| 编一个死循环、不打印的内核（或用 `sleep 100` 当命令） | 30 秒内结束，timed_out 处理正确 |
| 不需要 Docker 的纯函数（诊断解析、提示符切分、命令提取、GIC 识别） | 用 `contracts/examples` 和构造的字符串测，CI 上也能跑 |
