# 地址空间与内存保护

内核通过页表、MMU 和边界检查保护地址空间。指针或下标越界会破坏别的对象，轻则数据错乱，重则整机宕机。MiniEuler 跑在 QEMU virt 上，很多缓冲区是定长数组，写代码时必须同时核对长度与索引。

## NULL_DEREF 空指针解引用

空指针表示“没有合法对象”。在 C 里对 `NULL` 解引用（读写 `*p` 或 `p->field`）会触发异常或未定义行为。内核里若在中断/调度路径踩空指针，整系统会直接挂掉，比用户态段错误更难恢复。

MiniEuler 里常见于：任务控制块、信号量、shell 控制块指针未判空就使用；`PRT_TaskCreate` / 查找函数失败后仍当成功用。ARM64 上空地址附近通常不可映射，QEMU 里会进异常向量。

改法：所有“可能失败”的指针在解引用前判断；失败路径返回错误码并清理已分配资源。错误分支不要“假设一定非空”。

## OUT_OF_BOUNDS 数组越界

用超出 `[0, len)` 的下标读写数组，会覆盖相邻栈/堆对象。内核栈不大，一次越界就可能毁掉返回地址或别的任务的上下文。

MiniEuler 典型：`src/shell/shmsg.c` 里从环形缓冲取字符写入 `cmd[idx]`，若只递增 `idx` 而不与 `SHELL_SHOW_MAX_LEN`（或等价容量）比较，长输入或异常输入会写爆 `cmd`。读偏移 `shellBufReadOffset` 回绕时，写侧也必须保证不越界。

改法：写入前检查 `idx < 容量`；到达上限就丢弃、截断或报错，并保证环形缓冲的读写偏移对容量取模。循环上界用命名常量，不要魔法数字。

## WILD_POINTER 野指针

野指针指向已失效或从未初始化的地址：未赋值的局部指针、已释放的堆块、已销毁对象上的悬挂引用。解引用结果不可预期，可能“偶尔能跑”从而更难查。

MiniEuler 里注意：静态/全局指针初始化；任务退出或结构体复用后不要再拿旧指针；从缓冲读出的地址先当整数校验再当指针用。

改法：定义时置 `NULL`；释放或失效后立刻置空；生命周期结束的对象不要再被其它模块持有。需要跨模块传递时，用 ID + 查表，而不是长期保存裸指针。
