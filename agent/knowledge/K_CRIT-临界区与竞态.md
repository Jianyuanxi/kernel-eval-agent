# 临界区与竞态条件

临界区是访问共享数据时“必须独占”的那段代码。多任务和中断可能交错执行，若共享变量没有互斥保护，就会出现竞态：结果依赖谁先跑到，表现为偶发错误、丢字符、计数错乱。

## RACE 共享变量未加保护

竞态指两个（或更多）执行流同时读写同一共享状态，且至少一方在写，中间又没有锁/关中断等互斥。读-改-写（如 `x++`、链表摘节点）在单核上也可能被中断打断，看起来“原子”其实不是。

在内核里危险的原因：调度器和中断随时插入；shell 收包、时钟 tick、任务切换都会碰全局结构。竞态会导致环形缓冲读写偏移不一致、信号量计数值错误、就绪队列链表损坏，进而调度崩溃。

MiniEuler / UniProton 风格写法：

- 短临界区用 `OsIntLock()` 关中断，结束后每个返回路径都 `OsIntRestore(intSave)`。
- 若临界区内可能触发调度，用 `OsTskScheduleFastPs(intSave)` 一类接口在恢复中断的同时切任务，避免“锁还握着却切走”。
- 任务间同步用信号量 `PRT_SemPend` / `PRT_SemPost`（见 `prt_sem.c`），不要只靠“约定不会并发”。
- UART 接收缓冲、shell 环形队列的 `writeOffset` / `readOffset` 与任务侧消费必须在同一套互斥规则下更新。

改法：先标出所有共享变量和谁会碰它们（任务 / 中断）；给每个共享对象选一种互斥（关中断或信号量），保证读-改-写完整落在临界区内；关中断要短，长等待放在锁外用信号量睡眠。审查每个 `return`/`goto` 是否漏了恢复中断或 `V` 操作。
