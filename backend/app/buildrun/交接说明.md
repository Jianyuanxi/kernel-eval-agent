# 编译与运行模块交接说明

本次交付实现块三的编译、运行和公共沙箱能力。代码只位于 `backend/app/buildrun/`、`backend/tests/buildrun/`，未修改其他块的模块、冻结接口、依赖清单或沙箱 Dockerfile。测试服务器只用于本块独立验证，正式系统集成由负责人安排。

## 模块边界

| 使用方 | 提供给块三 | 块三提供的结果 |
| --- | --- | --- |
| 块二工程处理 | 合法的 `Project`、只读的工程根目录 | 按 `buildable` 决定编译或返回不支持，不重新识别工程 |
| 块一公共流水线 | 可写的独立 `work_dir` 和 `log_dir` | `BuildResult`、`RunResult`、构建与串口日志；工具故障抛 `SandboxError` |
| 块四静态分析 | 继续按现有签名调用公共沙箱函数 | `run_in_sandbox` 和 `prepare_workspace` 的签名不变；工作副本中保留编译命令 |
| 块五与块六 | 通过块一提供的工具或报告读取结果 | B/R 证据编号、警告错误数、启动状态、命令输出、功能提示 |

块三不负责上传与解压、源码差异、clang 扫描、知识库、智能体评审、评分、前端、报告导出或正式系统部署，也没有修改这些模块。

## 冻结接口

```python
build(project, project_dir, work_dir, log_dir) -> BuildResult
run(project, work_dir, build_result, log_dir) -> RunResult
run_in_sandbox(cmd, work_dir, timeout_s, *, name, stdin_steps=None, max_output=256*1024) -> ExecResult
prepare_workspace(project_dir, work_dir) -> list[str]
```

`project_dir` 为原件，模块只读。`work_dir` 是可丢弃的工作副本，不能与原件重叠。现有 `build/` 产物会在准备工作区时清除，防止复用旧缓存。符号链接不能用于读写工作区外内容。

`build.log`、`run.log` 写在调用方给定的日志目录中；`log_file` 返回真实文件路径，沿用任务说明，由块一现有流程转换成任务相对路径。产物路径和诊断源码路径使用相对路径及 `/` 分隔符。

## 状态与评分输入

`unsupported` 表示工程不可编译；编译未通过时运行返回 `skipped`。构建失败、超时、运行无输出或刷屏属于学生工程的检查结果。Docker、镜像、执行器或清理故障抛出 `SandboxError`，由流水线区分为工具错误，不能按学生编译失败扣分。

`BuildResult.warnings` 只统计工程内警告，不包含链接器等工程外警告。B 证据和命令的 R 证据均按顺序编号，启动证据固定为 R1。`RunResult.feature_hints` 只包含可直接观察到的功能迹象，后续模块仍须自行判断完成度与评分。

## 运行环境要求

使用 x86_64 Linux、Python 3.12、Docker 和镜像 `kernel-eval-sandbox:0.1`。宿主执行测试或后端的账号应为有 Docker 权限的普通用户；执行器拒绝将 root 身份带入学生容器。共享镜像和函数签名保持不变。

构建默认 180 秒，单次 QEMU 窗口默认二十秒，无串口输出时最多重试一次，整个运行默认六十秒内返回。每次执行结束后清理自己的容器；过期容器清理只处理当前用户带项目标签的实例。

安装、网络受限时的本机中转方法、参数及完整复现命令见 `指导书.md`。登录凭据、云 API 凭据、往届样例和原始验收日志不在 Git 仓库中。

## 已知样例差异

当前包里的 lab6_pro 在不同运行中既出现过两个任务完成，也出现过任务说明所述的异常刷屏。模块按真实输出分类，原样例测试严格校验对应状态；独立自写故障内核确保每次都验证刷屏、截断和时间限制。详见 `NOTES.md` 中的样例摘要和两种输出记录。

这一差异不改变 `RunResult` 状态规则，不需要其他模块迁就特殊目录名，也不应按文件夹名称硬编码失败。任务说明的维护和后续样例版本选择由集成方处理，块三未修改其他块拥有的文档。

## 集成步骤

1. 审核本块 PR，在目标环境安装或确认相同标签的镜像。
2. 以正式后端所用普通账号运行本块真实测试，确保没有 skipped。
3. 运行后端全量测试，检查公共沙箱与其他使用方兼容。
4. 由块一调整假数据模块配置，接入真实 `buildrun`；再完成网站和智能体的系统联调。

以上步骤是交接说明，块三没有修改正式服务或代替其他负责人执行集成。
