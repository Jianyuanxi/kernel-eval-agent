# 网页评分与追问（块 6）

## 1. 模块职责

块 6 负责把后端流水线结果呈现为可操作的网页，并实现百分制评分、Markdown 报告导出，以及基于同一 Dify 会话的缺陷追问。代码分布在：

| 目录 | 内容 |
|---|---|
| `frontend/` | Vue 3 + Vite 单页应用：上传、选工程、进度、报告、追问 |
| `backend/app/scoring/` | `compute_score`、`render_markdown` |
| `backend/app/followup/` | `answer_followup` |
| `acceptance/` | 一键验收脚本 `run_samples.py`、S12 截图、`result.md` |

前端只通过 `/api/...` 访问后端；本地开发时 Vite 把 `/api` 代理到 `http://127.0.0.1:8000`，部署后由 nginx 同域转发，**不要写死服务器 IP**。

## 2. 本地开发环境

### 2.1 依赖

- Python 3.12，`cd backend && pip install -r requirements.txt`
- Node.js（本机 v22/v26 均可），`cd frontend && npm install`
- 不建 `backend/.env` 时默认 **全部假数据**（`KE_MOCK_MODULES=all`），上传任意 zip 会得到样例 1 的报告（79 分），便于做报告页和追问 UI

### 2.2 启动

```bash
# 终端 1
cd backend && python -m uvicorn app.main:app --reload --port 8000

# 终端 2
cd frontend && npm run dev
```

浏览器打开 Vite 提示的地址（通常 `http://127.0.0.1:5173/`）。任务号使用 hash 路由 `/#/task/{task_id}`，刷新后会 `GET /api/tasks/{id}` 并按 `stage` 恢复到选工程、进度或报告页。

### 2.3 只测真实评分

在 `backend/.env` 中设置（复制 `deploy/env.example` 并删掉开头服务器路径行）：

```text
KE_MOCK_MODULES=ingest,buildrun,analyze,diff,agent
```

此时只有 `scoring`（及本块 followup）走真实实现，其余模块仍可用 mock。

## 3. 前端页面与接口

| 页面 | 路由 | 主要接口 |
|---|---|---|
| 上传 | `/` | `POST /api/tasks`（字段名 `files`） |
| 任务（选工程 / 进度 / 报告） | `/#/task/:id` | `GET /api/tasks/{id}`、`POST .../start`、`GET .../events?after=`、`GET .../report` |
| 报告内导出 | 同上 | `GET /api/tasks/{id}/export?format=json\|md` |
| 源码抽屉 | 报告页 | `GET /api/tasks/{id}/source?path=&start=&end=`（每次最多 200 行） |
| 追问 | 报告页 | `POST /api/tasks/{id}/followup` |

### 3.1 上传页

支持一个 `.zip` 或 1–50 个 `.c`/`.h`，总大小不超过 20MB。错误信息按后端 `error.code` 映射为中文（见 `frontend/src/api.js` 的 `formatError`）。

### 3.2 进度页

- 阶段条：编译 → 运行 → 扫描 → 对比 → 智能体评审 → 评分
- 每 2 秒请求 `GET /api/tasks/{id}/events?after=已有最大 seq`，只追加新工具调用
- `ToolTimeline` 按 `source` 着色：`pipeline` / `agent` / `followup`
- `stage === done` 时拉取报告并切换到报告组件；`failed` 显示错误

### 3.3 报告页（对应 docs/06 S12）

报告页顶部提供 **目录导航**（分项分数、编译运行、功能点、缺陷清单等），长报告可快速跳转。

必含内容：

- 总分、等级、工程名、模型、生成时间；**ECharts 雷达图**（只画 `score !== null` 的项，值为得分率）
- 四项分数卡片与 reasons；导出 JSON / Markdown
- 编译运行：诊断列表、可折叠 `log_tail`、运行输出与 shell 命令输出（等宽块）
- 8 个功能点：状态标签、理由、可点击源码位置
- 缺陷清单：级别、类型、`path:line`、知识点、建议、改前/改后；基线/学生改动标记；**追问**按钮
- 规范与创新、参考代码对比（创新点 C）
- 工具调用时间线 + 可折叠 `agent_thoughts`
- 追问框：选中缺陷或自由提问；答案用 **marked** 渲染；等待最长约 70 秒（与后端 60 秒超时对齐）

源码查看器为右侧抽屉，支持上下翻页（每次 200 行），当前行高亮。

## 4. 评分与 Markdown 导出

### 4.1 `compute_score`

- 输入：`ScoreInput`（build/run/features/defects/style/innovation/diff 等），输出 `ScoreResult`
- 百分制：**不要用 Python 内置 `round()`**（银行家舍入），统一 `int(raw / max_sum * 100 + 0.5)`，与 `docs/03` 及 `contracts/examples/score_result.json` 一致
- 会就地修改 `defects[i].counted`；测试里每次调用前应对 defects **`model_copy`**
- 功能点原因里的顿号/逗号用 **中文逗号**，名称来自 `FEATURE_NAMES`

实现拆在 `scoring/compute.py`，`__init__.py` 仅保留冻结签名。

### 4.2 `render_markdown`

- 在 `scoring/markdown.py` 生成与网页一致的 Markdown 报告
- `score is None` 的项写「不计分」；构建日志不在 Markdown 里塞完整 `log_tail`（网页用折叠块）

## 5. 追问 `answer_followup`

1. 读取任务报告与已有工具调用；`before = max(seq)`
2. 若带 `defect_index`，把缺陷格式化为 `[{severity}] {type_name} {path}:{line} {title}`，否则缺陷段为「（未指定）」
3. 用 `prompts.render("followup", ...)` 拼 query，调用 `dify.chat`，`user=task-{task_id}`，**必须带上评测时的 `conversation_id`**
4. 对返回 thoughts 里以 `dataset_` 开头的工具，用 `storage.append_tool_call` 补记 `source=followup, tool=knowledge`
5. 返回 `{ answer, tool_calls }`，**不修改报告、不重新计分**；`DifyError` 不捕获（API 层转 502）

测试可注入假 `DifyClient`，检查 query 含缺陷标题且报告文件未被改写。

## 6. 一键验收与截图

### 6.1 脚本

在 **服务器真实模式**（样例在 `/data/kernel-eval/samples`，各模块非 mock）下：

```bash
cd /path/to/repo
python acceptance/run_samples.py \
  --base http://132.232.242.186 \
  --samples /data/kernel-eval/samples \
  --out acceptance/result.md \
```

脚本检查 docs/06 的 S1–S11，输出 Markdown 表格；S8 引用块 4 的 `evaluation/result.md`。假数据模式下样例 2 往往识别不出 11 个工程，**失败是预期**；最终 `acceptance/result.md` 应在服务器跑通后再提交。

## 7. 构建与部署

```bash
cd frontend && npm run build   # 产出 frontend/dist，CI 必过
cd backend && python -m pytest -q
```

`package-lock.json` 必须提交；服务器部署时块 1 执行 `npm ci && npm run build`，nginx 静态托管 `frontend/dist`。块 6 **不需要自己 SSH 部署**。

## 8. 常见问题（摘自 NOTES）

| 现象 | 处理 |
|---|---|
| 假数据下追问一直 mock | `followup` 随 `agent` mock；要测真实追问需关闭 agent mock |
| Vite 改代码页面不更新 | 确认 dev 进程在跑；端口占用时可换端口 |
| 浏览器里 textarea 绑不上 | 自动化输入需触发 input 事件；手测正常即可 |
| 追问超时 | 前端 70s AbortController，后端 `FOLLOWUP_TIMEOUT_S=60` |
| 报告页源码打不开 | 假数据模式下路径必须在上传包内 |

更完整的踩坑记录见 `frontend/NOTES.md`。
